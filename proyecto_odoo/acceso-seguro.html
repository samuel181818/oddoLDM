Acceso seguro a la información

Roles, grupos y privilegios en Odoo.

Mecanismos de seguridad en Odoo

Odoo cuenta con un sistema de seguridad bastante completo. La idea principal es que cada usuario solo pueda ver y modificar la información que le corresponde según su puesto en la empresa.

Los principales mecanismos de seguridad son:

  • Autenticación: cada usuario tiene un login y contraseña personal.
  • Grupos (roles): cada usuario pertenece a uno o varios grupos, y cada grupo tiene unos permisos concretos.
  • Reglas de acceso (ACL): definen qué grupos pueden leer, crear, modificar o borrar registros de un determinado modelo.
  • Reglas de registro (Record Rules): filtros que limitan qué registros concretos puede ver un usuario (por ejemplo, "solo mis oportunidades").
  • Autenticación en dos pasos (2FA): se puede activar para añadir una capa más de seguridad.

Tipos de usuario

En Odoo hay tres tipos principales de usuario:

Tipo Para qué se usa
Interno Trabajadores de la empresa. Tienen acceso al backend (la interfaz completa).
Portal Clientes o proveedores externos. Solo pueden ver una parte limitada (sus pedidos, sus facturas...).
Público Cualquier visitante anónimo. Acceso muy restringido, solo a la parte web pública.

Grupos y roles

Para que un usuario interno tenga permisos sobre un módulo concreto hay que asignarle un grupo dentro de ese módulo. Por ejemplo, dentro del módulo de Ventas existen estos grupos:

  • Usuario: solo documentos propios — solo ve los presupuestos/pedidos que ha creado él.
  • Usuario: todos los documentos — ve los de todos los compañeros.
  • Administrador — además puede configurar todo el módulo.
[CAPTURA 1] · Asignación de grupos al editar un usuario

Para asignar los grupos vamos a Ajustes → Usuarios → (seleccionar usuario) y en cada módulo desplegamos el menú para elegir el nivel de permiso.

Ejemplo práctico

Para esta práctica he creado tres usuarios con roles diferentes:

  1. Admin general → acceso a todo.
  2. Comercial → solo Ventas y CRM, y únicamente sus propios documentos.
  3. Almacén → solo Inventario.
[CAPTURA 2] · Listado de usuarios creados con sus distintos roles

Después he iniciado sesión con cada uno para comprobar que el sistema funciona como se espera. Por ejemplo, al entrar con el usuario Comercial, en el menú principal solo aparecen las apps de Ventas, CRM y Contactos. El módulo de Inventario o de Ajustes no aparece.

Reglas de registro

Las reglas de registro son condiciones que se aplican a cada modelo y que filtran qué datos puede ver cada grupo. Por ejemplo, la regla por defecto del módulo CRM dice que un usuario del grupo "Usuario: solo documentos propios" solo puede ver las oportunidades donde él es el vendedor asignado.

[CAPTURA 4] · Pantalla de reglas de registro (con modo desarrollador activado)

Las reglas se pueden consultar desde Ajustes → Técnico → Seguridad → Reglas de registro (hay que tener activado el modo desarrollador).

Autenticación en dos pasos (2FA)

Cada usuario puede activar la autenticación en dos pasos desde su perfil. Una vez activada, además de la contraseña hay que introducir un código generado por una app como Google Authenticator o Authy.

[CAPTURA 5] · Activación de 2FA en el perfil de usuario
Buenas prácticas de seguridad:
  • Usar contraseñas largas y diferentes para cada usuario.
  • Activar la autenticación en dos pasos para los usuarios con más permisos (sobre todo el administrador).
  • No compartir cuentas entre varias personas.
  • Cambiar la contraseña del usuario maestro de la BBDD por una segura.
  • Revisar de vez en cuando los usuarios activos y desactivar los que ya no se usen.
